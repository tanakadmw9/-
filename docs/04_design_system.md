# 04 映像デザイン・テロップ・モーションの規定

全パートで使い回す前提の「型」。値は CSS 変数として1ファイル（例：`comp/styles/tokens.css`）にまとめ、各部品はそこから参照する。変更するときは decisions.md に理由を残す。

## 1. 方向性

- キーワード：**誠実・明快・あたたかい**。測量らしさは「地図・方眼・照準・点」で出す。
- 元映像の焼き込みテロップ（青い光沢カプセル）とは正反対の、**フラットで落ち着いた**見た目にする。
- 画面の主役は人と現場と図解。デザイン要素は脇役で、目立とうとしない。

## 2. 色（意味で使い分ける）

| トークン | 値 | 用途 | コントラスト確認 |
|---|---|---|---|
| `--ink` | #14202E | テロップの板、図解の文字 | 白文字 16.5:1 |
| `--navy` | #1F3A5F | **既知・基準**（△既知点、設計線） | 紙地の上で 10.2:1 |
| `--paper` | #F4F1EA | 図解の背景（紙） | |
| `--grid` | #D9D3C4 | 図解の方眼（細線） | |
| `--orange` | #E8742A | **はかる・新しい**（光の線、新点、角度の弧） | **図形専用**。紙地の上の文字には使わない（2.7:1で不足） |
| `--orange-dark` | #B8541A | 紙地の上でオレンジ系の文字が必要なとき | 4.3:1（大きい文字のみ） |
| `--white` | #FFFFFF | 実写上の文字 | |
| `--sub` | #C9D3DE | 実写上の補足文字 | 紺板の上で 10.9:1 |

- 色は上記以外を増やさない。赤と緑の組み合わせで意味を伝えない（色覚の多様性への配慮。実写は緑が多い）。
- 確認の✓も紺かオレンジで描く。

## 3. 文字

- 和文：**BIZ UDPゴシック**（Bold／Regular）。読み間違いの少ないユニバーサルデザイン書体で、子どもや年配の家族にも読みやすい。SIL OFL 1.1。
- 数字（座標など等幅が必要なところ）：**BIZ UDゴシック**。
- フォントは必ずプロジェクト内のファイルから読み込む（システムのフォントに頼らない）。ライセンス文も同梱する。
- サイズ（1920×1080基準・大画面上映を想定）：

| 種類 | サイズ | 太さ |
|---|---|---|
| 章タイトル | 104〜120px | Bold |
| キーワードテロップ | 64〜72px | Bold |
| ラベル（主） | 44〜52px | Bold |
| ラベル（補足） | 34〜38px | Regular |
| 最小 | **34px未満は使わない** | |

- 1行は最大16字、最大2行。改行は文節で手動で入れる（「、」「。」を行頭にしない、1字だけの行を作らない）。
- 表示時間 ≥ **文字数 ÷ 4 ＋ 1.0秒**、かつ最低1.5秒（日本語字幕の目安「1秒4文字」に、子どもと年配者のための余裕を足した値）。
- 行間 1.35前後。見出しは約物を詰める（`font-feature-settings: "palt"`）。

## 4. 配置

- 文字は**画面の90%の内側（タイトルセーフ）**に収める：左右96px・上下54pxより内側。推奨は左マージン132px。
- キーワードテロップは原則**左下**（下端から90px以上上げる）。人物の顔、TS、プリズムには重ねない。
- 説明ラベルは**対象物のすぐ横**に引き出し線で置く（画面下にまとめない）。
- 焼き込みテロップの扱い（切り出し／覆う）は docs/02 §3 に従い、Phase 3 で決める。

## 5. 部品

| 部品 | 仕様 |
|---|---|
| 章タイトル | 照準（細い十字線＋目盛り）が対象に合う → 中心の点がオレンジに点る → 「基準点測量」→ サブタイトル。小さく分野名「測量」。背景が明るいときは下からの紺のグラデーション（不透明度は最小限）で文字を守る |
| キーワードテロップ | 紺の板（不透明度88%、角丸6px、余白 縦18px・横28px）＋左端にオレンジの縦線6px。白文字 |
| 用語カード | 用語（Bold）＋ひとこと説明（Regular）の2段。「基準点＝位置の“ものさし”になる目印」 |
| 対象ラベル | 対象物の上の小さな点（直径10px）→ 白の引き出し線2px → ラベル板。板は紺88% |
| 図解の記号 | 既知点＝紺の△（中心に点）、新しい点＝オレンジの◎、光の線＝オレンジ5px（端は丸く、ごく弱い発光）、角度＝オレンジの弧、設計線＝紺の点線、線幅は4〜6px |
| 締めの一文 | 章タイトルと同じ書体と配置ルール。最後に照準が一点に戻る |

## 6. 動き（モーション）

- 入り：0.4〜0.6秒、減速（GSAP `power3.out`）。フェードと16〜24pxの持ち上がり、またはマスクで現れる。
- 出：入りより短く0.25〜0.35秒（`power2.in`）。
- 移動：`power2.inOut`。**バウンス・エラスティックは使わない**。
- 同時に動くのは1か所。次の動きは前の動きが終わってから（重ねる場合は0.1〜0.2秒ずらす）。
- 長い文の一文字ずつのタイプライター表示はしない（読むのが遅くなる）。数字のカウントアップは可。
- 静止画をゆっくり動かす（パン・ズーム）のは、見せたい所へ視線を運ぶ理由があるときだけ。拡大の速さは毎秒5%以下。
- 光の点滅は1秒間に3回を超えない（光過敏への配慮）。

## 7. 実写の画づくり

- まず全カットの色をそろえ（晴天・曇天の差をならす）、その上で全体の「調子」を1つ決める：緑の彩度をやや下げ、わずかに暖かく、黒を少し締め、ハイライトを抑える。
- 圧縮素材なので**強い補正は禁止**（バンディングやブロックが出る）。シャープは足さない。空にはデバンド、全体にごく薄いグレイン（粒子）を足して圧縮ノイズをなじませるのは可。
- 拡大は1.2倍程度まで。1.2倍を超えるカットは大画面での見え方を確認し、比較画像を残す。
- 色の候補は2〜3案を同じフレームに並べて比較し（`hyperframes grade-compare` など）、人間が選ぶ。

## 8. やってはいけないこと（「AIっぽい雑な編集」の具体例）

- 全カットに同じズームやパンをかける
- 汎用のトランジション（ワイプ、回転、グリッチ、光漏れ、フラッシュ）
- ナレーションの全文を字幕で出す
- 意味のない効果音（キラーン、シュッの連発）
- 絵文字、ストック風の汎用アイコンやイラストの多用
- グラデーション・ドロップシャドウ・光沢の多用、立体ボタン風のテロップ
- 文字だけのカードを画面中央に何枚も続ける
- BGMを頭からベタ流しして、フレーズの途中でフェードアウトして終わる
- 音楽の拍とまったく関係のないカット割り
- 説明の「挿絵」止まりで、動きが理解を生んでいない図解
- 説明していない専門用語、根拠のない数字
- 実在の人物・現場をAIで生成した画像や映像（記録映像としての信頼を損なう）

**ルール：絵コンテのすべての要素に「目的」欄を書く。目的を一言で書けない要素は入れない。**
