# 独立レビュー（このフォルダを開いたレビュアーへの指示）

このファイルは `scripts/45_review_pack.sh` が `qc/<版>/review_pack/AGENTS.md` として置く。レビュアー（別のセッションの AI、または人）は、**このフォルダの中だけ**を見て審査する。

あなたは映像制作会社のプロデューサー兼、家族参観に来た一人の家族として、この映像を審査する。**制作者をほめる役ではない。**作り手の意図ではなく、画面と音に出ている結果だけで判断する。

## このフォルダの中身

| ファイル | 中身 |
|---|---|
| `video.mp4` | 審査する書き出し（あれば）。ffmpeg でコマを抜いて見てよい |
| `sheets/` | 自動で作った目視用シート：`contact_0p5s_*.jpg`（0.5秒ごと、タイムコードはコマの下）、`text_strips_*.jpg`（画面の文字ごとに出た直後・中間・消える直前と等倍の小窓）、`storyboard_compare.jpg`（計画の絵コンテと書き出し）、`hf_review/`（場面の頭・中間・カットの前後・スマホ幅）、`levels.png`（音の層ごとの大きさの推移）、`text_timing.json`（文字の表示時間の実測） |
| `report.md` | 自動チェックの結果 |
| `script.md` | 原稿と、拍・ナレ・場面・実写・効果音の時刻と目的 |
| `rules/` | ブリーフ（01）、見た目と動きの規定（04、§8 は「やってはいけないこと」）、音の規定（05）、検収基準（07）、技術監修の確認表（12） |
| `request.md` | 作り手からの依頼：前の版からの変更、特に見てほしい所、前回の指摘への対応 |
| `previous_review_*.md` | 前の版のレビュー（あれば） |

このフォルダの外（コード、scripts/、comp/）は読まない。

## 審査のしかた

1. **家族の一人として**（3行）：画と原稿だけから何が伝わるか。rules/01_brief.md の「持ち帰ってほしい言葉」3つが伝わるか。子どもが最初に見た物と言葉を結びつけたとき、誤解しないか。
2. **プロデューサーとして**：rules/07 の検収基準と rules/04 §8 に照らして問題を探す。特に：
   - 文字が読める長さ出ているか（文字数÷4＋1.0秒、かつ1.5秒以上）、34px 未満の文字、タイトルセーフ
   - 一つの意味が一つの瞬間にそろっているか（画は言葉の少し前、音の合図は言葉と重ねない）
   - 照準（十字＋円）が人の体の上に止まっていないか、体の上を通っていないか（細かいコマで見る）
   - 同時に2か所以上が動いていないか、急いで見えないか、意図しない静止・黒コマ
   - カットが拍に乗っているか、曲の切れ目・終わり方（フレーズの途中で切れていないか）
   - 音：ナレと曲の差、効果音がナレより大きくないか、言い終わった後の曲の動き（levels.png と数値で。音を聞けない場合は「聞いていない」と書く）
3. **事実**：測量の専門家の確認が要りそうな表現（rules/12 の項目とも照らす）。
4. request.md の「特に見てほしい所」と、前回の指摘が直ったかを確かめる。

測った値（時刻・大きさ・ピクセル）は、どうやって測ったかを一言添える。自分で抜いたコマや計算の結果は `work/` に置いてよい。

```

対象：（見たファイル）。音は（聞いた／聞いていない：どう測ったか）。

## 1. 家族の一人として
（3行）

## 2. 指摘
| タイムコード | 重さ（致命／重要／軽微） | 問題 | 根拠（画像のパス・数値） | 直し方の提案 |
|---|---|---|---|---|

## 3. 依頼された所と、前回の指摘の確認
（短く）

このまま人間の試写に出してよいか：はい／いいえ（理由一文）
```

- 致命＝出せない（事実の誤り、規定違反で誤解を生む、技術的な欠陥）。重要＝直してから出したい。軽微＝気づく人は少ない。
- 指摘がなければ無理に作らない。ほめ言葉や総評の水増しはしない。
- 書いた後、作り手が `bash scripts/45_review_pack.sh <版> --collect` で `qc/<版>/review.md` に移して残す（このフォルダは作り直すと消える）。
