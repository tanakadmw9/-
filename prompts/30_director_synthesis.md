# 監督の統合（担当レビューの後）

使い方：担当レビュー（reviews/<版>/*.md）がそろったら、監督のセッション（メインの制作セッション）に渡す。
依頼者の言葉：「監督として、各担当スレッドの改善案をまとめるだけでは監督の意味がない。あなたの能力がすべてを左右する」。

---

```
reviews/【v4.6】/ の担当レビューを全部読み、監督として次の版【v4.7】の方針を決めてください。案を数で取り込むのではなく、原則で選び、捨ててください。

原則（playbook/00_summary.md）：
1. 一つの意味は一つの瞬間に（画は言葉の少し前、音の合図は言葉と重ねない）
2. 子どもは最初に見た物を言葉に結びつける
3. このパートの仕事は「【基準点をつくる】」
4. 「間」は音楽に渡す
5. 意見が割れたら 正確さ ＞ わかりやすさ ＞ 好み

やること：
1. 担当の案をすべて「採用／見送り／依頼者に選んでもらう」に分ける。担当どうしでぶつかる案は、原則の順で決め、理由を書く。
2. 担当が誰も挙げていない問題を、自分で書き出したコマと数値から探して足す（監督の推論）。
3. 採用した案を実装の順に並べ、時刻・数値・文言まで具体にする。尺（24小節の格子）と、壊してはいけないものは守る。
4. 書くもの：
   - 監督メモ（docs/ か reviews/<版>/director.md）：
     - 採用した改善の表：| 場所（時刻） | 変えたこと | ねらい | 出典（担当の案の ID） |
     - 見送った案と理由：| 案 | 判断 | 理由 |
     - 依頼者に選んでほしいこと：| # | 選ぶこと | 今の版 | ほかの案 | 監督のおすすめ |（比べられる試聴・比較ファイルを用意）
     - 既知の問題と、技術監修に聞くこと
   - docs/decisions.md への追記（採用・見送り・依頼者待ちを1行ずつ）
5. 実装 → 書き出し → QC → 独立レビュー（playbook/10_process.md §2.6）。
```

## 今回の実例（v4.7）

- 約60件の案 → 採用は冒頭の N1 の分割、「その目印を」を D0 の頭へ、D1 の札の言葉、効果音の差し替え、ミックスの測り方の修正、カットごとの色の跳びを減らす、など。
- 見送り：木杭を目印に使う（仮杭なら誤り）、S01 に「目印」の札（地面の点が画の外）、D1 の背景を流れる実写に（効果に対して手間が大きい）、尺を延ばす（格子と曲の構成がこの版の強さ）。
- 依頼者待ち：N6 の言い方、効果音、環境音、読点の間、ヘルメットの社名。
- 書いた後、書き出した絵を細かく通して自分で見て、自分の変更が生んだ問題を2つ見つけて直してから出した（「はじまりの点」の最中の1コマの黒、点つなぎの帯が△にかぶる）。
