# 60 次のパート（水準・地形・路線・用地…）を同じ型で作る

基準点測量パートは、部門のほかの作業パートの**型（テンプレート）**としても作った（reference/plans/editing.md §11）。ここでは、この一式を複製して次のパートを作る手順と、作業ごとに入れ替える所を書く。

## 1. 型（24小節、約60秒）

| 小節 | 役割 | 基準点測量での中身 | 入れ替える所 |
|---|---|---|---|
| 1 | 章扉 | アイコンの列、基準点だけ灯る | 灯るアイコン（`active`） |
| 2〜3 | タイトル | 照準がプリズムに合う → 作業名＋サブ | 作業名・サブ・背景の実写1カット・照準の行き先 |
| 4〜6 | 現場 | 歩く一行 → TS を据える2人 | 人と道具の実写2カット |
| 7〜8 | 用語 | 地面のしるし（D0） | その作業の主役の物を図解1つで |
| 9〜14 | しくみ | 実写 → 静止 → ラベル（D1）→ 倒れて真上の図（D2） | 仕組みを1つだけ |
| 15〜17 | 人 | のぞく・記録する・見渡す | 確かめる・記録する人の実写 |
| 18〜20 | 部門の中での役割 | 点つなぎ：等高線・道路の線、アイコンが線を受けて灯る | ほかの作業とのつながり |
| 21〜24 | 締め | 実写2カット＋締めの一文＋照準が章扉のアイコンに戻る | 締めの一文 |

共通にするもの：tokens.css（色・文字・動き）、章扉、タイトルの組み方（小見出し「測量部門のしごと」）、ラベル、キーワードテロップ、エンドカード（照準がアイコンに戻る）、効果音の合図（照準が合う「ピッ」はシリーズ共通）、ラウドネス −24 LUFS / −2 dBTP、色補正の基準。

曲：部門の全パートを続けて流すなら、同じ曲を使い回すか、パートごとに変えるかを**部門全体で**決める。型はどちらでも成り立つ（前奏の1小節が静か、最後に自然な終わりがある曲であること）。テンポが違う曲なら、拍と小節の値を変えるだけで格子が作り直せる。

## 2. 手順

1. **一式を複製**し、新しいリポジトリ（または別ブランチ）にする。docs/decisions.md は新しく始め、基準点の記録は reference/ に残す。
2. **ブリーフ**（templates/brief.md）：このパートが運ぶものを一文で。持ち帰る言葉3つ。背負わないもの。
3. **素材分析**：`source/input.mp4` を置き換え、`bash scripts/01_analyze.sh`（カット検出とシート）。
   - `scripts/01_analyze.sh` と `scripts/02_intermediates.py` の `CUTS`（カット境界）、`02` の `CROPS`（焼き込みを外す窓）、`GRADES`・`SHOT_ADJ`（色）、静止フレーム（`stills`）を新しい素材に合わせる。
   - 焼き込みテロップの見た目が違えば、`40_qc.py` 冒頭の検出条件（HSV）を元素材で調整し直す。
   - analysis/shot_log.md（templates/shot_log.md）。足りない画を書く。
4. **内容計画と編集計画を別々に**（templates/content_plan.md、editing_plan.md）。前のパートと同じ説明を繰り返さない（部門の一覧は章扉に任せる）。
5. **曲**：決めたら `scripts/41_bgm_structure.py` で曲の地図（小節ごとの強さ）を作り、編集点を決める。`scripts/34_prep_bgm.py` の引数（最初の拍、拍の周期）と、`timeline.bgm`（bars、hold）を直す。
6. **原稿**：`comp/narration.json`（id、text、keywords、vv_kana、vv_dir）。仮ナレを作る：`python3 scripts/11_tts_voicevox.py 14 audio/vo_temp 1.0 1.1 1.4 0.04`。
7. **尺の計画**：`scripts/20_plan_timeline.py` の B1〜B8 を書き直す。ここが正本の作り方そのもの。
   - 道具：`at(bar, beat)`（小節・拍→秒）、`cut(bar, beat)`（1コマ前）、`shot()`、`still()`、`scene(id, start, end, cues, purpose, variables=…)`、`vo(id, start)`、`kw(id, start, 語)`（語の時刻）、`se()`、`move()`、`beat(id, start, end, purpose)`。
   - **すべての shot・scene・beat に purpose（目的）を書く**。目的が書けない要素は入れない。
   - 意図した静止は `intended_freezes`、読ませない文字は `text_exceptions` に理由つきで。
8. **図解の部品**：`comp/compositions/` の d0・d1・d2・map_link をその作業の図に作り替える（docs/08 の約束：`cues` と `dur` を受け取る、`gsap.timeline({paused:true})` を1つ、`fromTo` を使う、乱数・時刻を使わない）。1場面だけの確認は `python3 scripts/21_build_index.py --scene <id>` と `npx hyperframes snapshot dev/<id> --at …`。
9. **章扉とエンドカード**：`chapter_door.html` の作業の並び（【要確認】部門の実際の作業名と順）と `active`。`endcard.html` の締めの一文。
10. **書き出し → QC → 独立レビュー → 直す** を繰り返す（10_process.md §2.6）。
11. **技術監修**：docs/12_kanshu.md を、その作業の確認事項に書き直す。

## 3. 作業ごとの考えどころ（叩き台。事実は監修で確かめる）

| 作業 | 主役の物（用語の図解） | しくみ1つ | ほかの作業とのつながり |
|---|---|---|---|
| 水準測量 | 水準点、標尺 | 2本の標尺を水平に読んで高さの差をはかる 【要監修】 | 基準点に「高さ」をつける |
| 地形測量 | 地形（等高線） | 基準点を使って地物の位置と高さを集める 【要監修】 | 地図・設計の土台になる |
| 路線測量 | 道路の中心線 | 設計した線を現地に出す 【要監修】 | 道路の図面と工事 |
| 用地測量 | 境界杭 | 土地の境界を確かめてはかる 【要監修】 | 道路などに必要な土地 |

## 4. 気をつけること

- 前のパートと**同じ言葉・同じ図を何度も見せない**（上映全体でくり返しになる）。共通なのは枠（章扉・タイトル・締めの形）だけ。
- 「新しい」「わかっている」の色の意味（オレンジ・紺）は全パートで同じにする。
- 子どもが最初に見る物と、言葉を結びつける（その瞬間に何が映っているか）。
- 部門の実際の作業名・並び、社名の入ったヘルメット、出演者の上映同意は、毎パート人に確かめる。
