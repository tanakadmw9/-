# 40 落とし穴（実際に起きたこと）

「症状 → 原因 → 見つけ方 → 直し方・防ぎ方」。同じ失敗を二度しないために、直した仕組み（スクリプト・QC・規定）も書く。

## 1. 映像

| 症状 | 原因 | 見つけ方 | 直し方・防ぎ方 |
|---|---|---|---|
| 1コマだけ黒が入る（v4.1、1:10.4） | 開始と長さを別々にフレームへ丸めたため、隣の要素とのすき間が1コマできた | 独立レビュー。blackdetect（0.1秒以上）では見つからない | 終わりもフレームに丸めてから長さを出す `span()`（20_plan_timeline.py）。QC に「1コマの黒」検査 |
| 照準が人の腰・背中に止まる、体の上を通る（v4.7） | 照準の通り道を、画の中の人の位置と照らし合わせていなかった | 独立レビュー（重要）。コンタクトシートの0.5秒おきでは通過が抜ける | docs/04 §5 に規則。照準が見える区間は細かいコマで通して見る。人のいない空・草地でカットをまたぐ |
| 実写が倒れるとラベルの点が対象から離れる（v4.8） | ラベルを写真と別の層に置いていた | 独立レビュー | ラベルを写真の層の中に置き、一緒に動かす（D1） |
| 前の場面の線と点が、次の場面の頭で完成して見える（v4.5） | 場面をまたいで持ち込んだ物を、そのまま表示した | 独立レビュー | いったん薄い影にして、言葉に合わせて現す |
| 焼き込みテロップの端が映る | 切り出し窓の y が影の分だけ足りない | QC の焼き込み検出（HSV、4fps 全画面） | 影を含めて窓を決める（S01・S02 は y<765）。素材が変わったら検出の条件を元素材で調整し直す |
| 書き出しごとに S05〜S08 の見え方が少し違う | H.264 の符号化の揺らぎ（中身は同じ） | 版の比較 | 差分を探すときは、中間素材か同じ設定の書き出しどうしで比べる |

## 2. 意味・内容

| 症状 | 原因 | 見つけ方 | 直し方・防ぎ方 |
|---|---|---|---|
| 子どもが「基準点＝オレンジの的」と覚えそう（v4.6） | 「その目印を」をプリズム（S03）の大写しの上で言っていた | 監督の推論（「子どもは最初に見た物を言葉に結びつける」） | 言葉を D0（地面のしるし）の頭に遅らせ、言葉「基準点」でしるしが灯る |
| 確かめる前の点を「新しい基準点」と呼んでいた（v4.7） | 図解の都合で名前を先に出した | 独立レビュー＋正確さ監修 | 名前は事実の順に。点つなぎで◎が△に変わる所で初めて呼ぶ |
| 構成が「基準点だけで部門を背負う」 | このパートの役目を決めずに作り始めた | 依頼者の指摘 | 最初に「このパートが運ぶもの」を一文で決める（10_process.md §2.1） |
| 木杭の画を「目印」に使いたくなる | 仮杭なのか基準点なのか、画からはわからない | 正確さ監修 | 事実が確かめられるまで使わない。【要監修】に残す |

## 3. 音

| 症状 | 原因 | 見つけ方 | 直し方・防ぎ方 |
|---|---|---|---|
| BGM が常に3dB低い（v4.6 まで） | ナレをモノラルのまま測り、ステレオの曲と比べていた | 音の担当の再計算 | ナレを2チャンネルにしてから測る（30_mix.py） |
| 曲が下がりすぎて平板 | 曲の大きさを90%点で測って大きく見積もった。短いすき間の上げに上限 | 音の担当の測定と試聴用 mp3 | 区間の平均で測る。すき間は上げきって0.25秒保てる所だけ上げる |
| 効果音がナレ中に聞こえない（v4.6） | 自作の合成音のエネルギーが声の帯域（1〜4kHz）にあった | 音の担当 | 帯域の外にエネルギーがある音（鉄琴・電子音）にする。BGM は声の帯域だけナレ中 −4dB |
| 読点の間がそろいすぎて機械的 | 間の倍率を全文一律にした | 依頼者「機械感」 | 文ごとの vv_dir（pause_before、end）。読点ごとの長さは未決 |
| 締めで和音が鳴っているうちに切れる（v4.7） | 画の黒へのフェードに合わせて曲を切った | 独立レビュー | 最後の和音を3秒のばす（bgm.hold）。曲のフェードを画より0.45秒早く始める |
| 言い終わった後に曲が「ふくらむ」（v4.9） | 減衰中の和音を0.35秒で持ち上げた | 独立レビュー | 1.0秒かけて +6dB。声の帯域の削りは残す |
| 曲のつなぎ目が聞こえる（v4.4、0:41） | 拍の途中や構成の切れ目でない所でつないだ | 試聴（人）と波形 | 小節の頭だけでつなぐ。つなぎ目は画の段の変わり目に隠す（D2、30.336秒） |

## 4. 検査（QC）そのもの

| 症状 | 原因 | 直し方・防ぎ方 |
|---|---|---|
| 文字の表示時間が「0/0 で PASS」 | 検査が timeline の telops だけを見ていて、場面の中に書いた文字を数えていなかった | 画面の DOM を0.05秒ごとに測る 44_text_timing.mjs。**0件は FAIL** |
| シートのタイムコードが文字を隠す、小窓が等倍でない | シートの作り方 | タイムコードをコマの下に、等倍の小窓に「1:1」と書く |
| 絵コンテとの比較で「計画の画」が古い | 計画のシートが前の版の書き出しから作られていた | 比較画像に注記を入れる |
| 自分の作品の自己チェックでは毎回合格 | 作った理由を知っている目で見る | 独立レビュー（別セッション、コードを見せない） |

## 5. 環境・ツール

| 症状 | 原因 | 直し方 |
|---|---|---|
| 44_text_timing.mjs が動かない | HyperFrames の内部ファイル名（`chunk-*.js`）に依存。版を上げると名前が変わる | HyperFrames は 0.8.206 に固定（package.json と package-lock.json）。上げるなら 44 の import を直す |
| Docker の VOICEVOX が途中で止まる（クラウド） | dockerd を `&` で起動、または背景タスクの既定の時間制限 | dockerd は長い時間制限の背景タスクで起動（50_environment.md §3） |
| Docker Hub が 429 Too Many Requests | 匿名の取得回数の制限 | `mirror.gcr.io/voicevox/voicevox_engine:cpu-latest` から取る |
| DOVA-SYNDROME に届かない | 2026-09-15 に OpenTracks（opentracks.com）へ改称 | 許可リストに opentracks.com（と dova-worker.tracks-cid.workers.dev） |
| 国土地理院のサイトに届かない（クラウド） | プロキシで遮断 | 事実確認は reference/research/kijunten.md。足りなければ人に調べてもらう |
| Git のタグを push できない（クラウド） | セッションのプロキシがタグを拒否 | 版はコミットの題「v4.x：…」で探す。タグはローカルだけ |
| 元映像が消えている | source/ は .gitignore。クラウドのコンテナは使い捨て | media の zip から戻す。共有フォルダに控えを置く |
| 書き出しに約10分かかる | 全編を Chromium で描く | 1コマの確認は `npx hyperframes snapshot comp --at t1,t2 --no-end`（約1分）。1場面だけは `python3 scripts/21_build_index.py --scene d2_topview` |
| HyperFrames が画面の文字を外部に送る機能 | `snapshot --describe`、`publish` 等はクラウドを使う | 使わない（AGENTS.md の禁止リスト） |
